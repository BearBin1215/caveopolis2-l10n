# 翻译规范

## 基本风格

- 使用规范的简体中文，标点使用全角符号。
- 物品、方块、实体、界面和提示使用中文。
- 模组名称、整合包名称和没有通行中文译名的专有名词保留英文。
- 不翻译资源 ID、标签、键位名称、文件路径和模组内部标识符。
- 不确定的内容不要猜测，先请用户决定；确认后写入 `glossary/terms.csv`；无法用翻译键覆盖的配置改动，在源码对应位置就近说明。

## 格式保护

以下内容必须与英文原文一致，数量和顺序都不能变：

- 占位符：`%s`、`%d`、`%1$s`、`%2$d`。
- 格式代码：`§a`、`&l`、`\n`。
- 标签：`{}`、`{image:...}`、`{@pagebreak}`。
- 原始 JSON 文本组件和其中的 `clickEvent`、`hoverEvent`、`keybind`。

`tools/validate.py` 会按条目比对占位符（严格顺序）和格式代码（只比数量）。

## 任务书

### 标题

章节标题、任务标题、任务副标题和任务要求标题只写中文，不附英文。

### 正文

正文使用中英双语，**按语言整段分块**：先连续输出全部中文段落，再输出一条分割线，最后连续输出全部英文段落。中文段落之间、英文段落之间各用一个空字符串分隔。

```json5
"quest.0000000000000000.quest_desc": [
  "中文第一段。",
  "",
  "中文第二段。",
  "",
  "&8───────────────",
  "",
  "English first paragraph.",
  "",
  "English second paragraph."
]
```

- 分割线由 `tools/build_quests.py` 的 `DIVIDER` 生成：`&8` + 15 个 `─`，不要手工改动长度。
- 英文段落与英文原文逐行一致，并保留原有的颜色和加粗代码。
- 译者只维护 `tools/quests_zh/<章节>.json` 中的中文段落，英文由脚本自动附上。
- 图片标签、分页标签和纯资源 ID 行不重复英文。
- 原始 JSON 文本组件先翻译组件内的文字，组件本身会作为英文块的一部分保留。
- 标题里的格式代码保留，例如 `&a地狱&f`。

### 校验

`tools/validate.py` 会检查任务正文的以下内容：

1. 所有中文段落必须位于英文段落之前；
2. 中文部分的占位符与格式代码必须和原文一致；
3. 英文段落必须与 `en_us` 原文逐行一致；
4. 分块前先去掉分割线，避免把分割线当成英文段落。

## 模组文本

- 物品名使用“物品类别 + 名称”的常见顺序，例如 `Copper Mesh` 译为“铜滤网”。
- 工具提示保持简洁，避免逐字直译。
- 罗马数字统一使用大写：`I`、`II`、`III`。
- 温度、能量、流体等单位保留英文缩写：`RF`、`FE`、`mB`；时间单位 tick 译为“刻”。
- 术语以 `glossary/terms.csv` 为准；新增术语先补表再使用。

## KubeJS 与配置

- 自定义物品名称、说明和玩家提示改用翻译键，并在 `kubejs/assets/` 中补充 `zh_cn` 语言文件。
- 不支持翻译键的配置直接写中文，改动位置由源码本身说明。
- 脚本改动只保留必要内容，方便整合包更新时合并。
- 方块名称使用 `block.<namespace>.<id>` 键，例如 `block.caveopolis.speedy_ladder`。

## 来源优先级

1. 本仓库 `resourcepack/` 中已有的译文。
2. 模组自带 `zh_cn`。
3. CFPA i18n 资源包。
4. 作者其他整合包的人工汉化（`.agents/references/translation-human/`）。
5. 新翻译。

模组自带中文与 i18n 资源包冲突时保留模组版本；必要时告知用户。其他整合包的译名只作参考，不直接覆盖本整合包已确认的术语。
